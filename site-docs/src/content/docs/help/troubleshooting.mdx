## Capture

### My windows don't appear (macOS)

Kimochi needs **Screen Recording**. Until it is allowed, the source picker shows
**Allow Screen Recording…** and the grid says **No windows to read. Enable Screen Recording for
Kimochi in System Settings.** Turn Kimochi on in **System Settings → Privacy & Security → Screen &
System Audio Recording**, and reopen Kimochi if macOS asks.

### Screen Recording is on, but capture is still refused (macOS)

macOS ties the permission to how the app was signed. If you switched between builds (for example a
nightly and a release), System Settings can show Kimochi as allowed while capture is refused. Reset
the old grant in Terminal, then allow Kimochi again:

```sh
tccutil reset ScreenCapture dev.kimochi.app
```

### I can't pick a window on Linux

On Wayland your desktop chooses what Kimochi may capture: use **Change source → Choose New Source…**
and pick the window in your desktop's dialog. If the dialog closes or times out, nothing was shared;
try again. On X11, minimised windows and windows on other workspaces aren't listed.

## Scanning

### A scan adds nothing

Watch the Log's activity ticker:

| Message | What to do |
| --- | --- |
| **Choose a source before scanning** | Pick a window or screen in the sidebar. |
| **Nothing recognised** | Crop to the text box, or try another [OCR engine](/reading/ocr-engines/). |
| **Same text as before, not added** | The text hasn't changed since the last scan. |
| **Capture failed: …** / **The source is gone: …** | The window closed or moved; choose it again. |
| **OCR failed: …** | The engine had a problem. For online engines, check your connection. |

To see exactly what the OCR found, turn on **Settings → General → Diagnostics → Debug overlay**: it
marks the scanned text boxes over the source and opens the Diagnostics window, which shows the last
capture (**Preview**), the box positions (**Coordinates**) and a **Capture test**.

### Auto OCR stopped

After several failed scans in a row Auto OCR pauses (**Auto-scan paused: it failed several times in a
row**). Fix the cause (often the source or the connection), then turn Auto OCR off and on again.
Manual scans still work meanwhile.

### Furigana or small text gets in the way

Keep **Filter out furigana and small text** on (**Settings → OCR & Overlay**). To change how much
it removes, open the arrow beside its switch and move **Filter strength** towards Strong (more
removed) or Gentle (less). A crop area around the dialogue also helps.

### Google Lens stopped working

Kimochi uses the service Chrome's Lens uses, which is not a published API, so Google could change or
stop it at any time. Switch to another engine, such as PaddleOCR, in the meantime.

## The overlay

- **The overlay is slow or choppy on macOS**: Game Mode is throttling it. See
  [Game Mode](/install/macos/#game-mode).
- **Show overlay reads "Overlay unavailable"** (Linux, Wayland): your desktop doesn't support the
  overlay yet. See [The overlay on Wayland](/install/linux/#the-overlay-on-wayland).
- **Nothing happens when I hover**: hold <kbd>Shift</kbd> (10ten needs no key; see [Which key to hold](/lookups/looking-up/#which-key-to-hold)) and
  check that a dictionary is set up (next section).

## Shortcuts

- **The game skips text when I press the scan shortcut**: some visual novels skip while
  <kbd>Ctrl</kbd> is held. Use a shortcut without it, such as the default <kbd>Shift+F8</kbd>, in
  **Settings → Shortcuts & Controls**.
- **"Mouse buttons need Accessibility"** (macOS): allow Kimochi under Accessibility in
  **Settings → Sources → macOS permissions**, then record the button again.
- **"Mouse buttons can't be shortcuts here"**: mouse buttons work on Windows and macOS, not yet on
  Linux. Use a key instead.

See [Keyboard shortcuts](/reference/shortcuts/).

## Dictionaries

- **No definitions found**: Yomitan needs a dictionary that is installed *and* enabled in its
  current profile. Open **Settings → Dictionary → Open Yomitan settings** and enable one, or
  run the welcome guide's **Install Jitendex** again.
- **"An incomplete Jitendex import already exists"**: remove the half-imported Jitendex in the
  dictionary settings, then retry.
- **The engine won't download**: check your connection and press **Retry**, or choose another
  engine. Downloads resume where they stopped.
- **My dictionaries disappeared (macOS, building from source)**: run the app bundle, not the bare
  executable, which gets different web storage.

## Anki

With the Yomitan API, **Settings → Anki** shows what's wrong with the connection, and checks again
every few seconds while it's open:

- **Not running**: open Anki, and make sure the
  [AnkiConnect](https://ankiweb.net/shared/info/2055492159) add-on is installed.
- **Wrong port**: the **Address** doesn't match AnkiConnect's `webBindPort` (default
  `http://127.0.0.1:8765`). If AnkiConnect answers at the default address, a button switches to it.
- **API key needed** or **Wrong API key**: AnkiConnect's config has an `apiKey`. Enter the same key
  under **API key**.
- **Yomitan or Hachidori can't reach Anki**: check the AnkiConnect address (and API key, if you set
  one in AnkiConnect) in the dictionary's own Anki settings: **Settings → Anki** has a button to
  them. You don't need to add anything to AnkiConnect's `webCorsOriginList`.

- **Cards have no sentence audio**: check that **Enhance Anki cards** is on and that **Settings →
  Anki → Card enhancement** shows no problem. On macOS it needs Screen Recording; on Linux it needs
  PipeWire. Recording starts only once the speech model is downloaded. Check the **Audio field**
  matches your note type. A card only gets audio for a line that arrived within **Seconds kept**,
  and never into a field that is already filled.

See [Anki](/lookups/anki/#the-ankiconnect-connection).

## Linux

- **The AppImage won't start**: install FUSE 3 (`sudo apt install fuse3`, `sudo dnf install fuse3`,
  `sudo pacman -S fuse3`, `sudo zypper install fuse3`), or use the one-line installer, which sets
  Kimochi up to run without it. See [Install on Linux](/install/linux/#if-kimochi-wont-start).
- **"GitHub's download limit was reached"** from the installer: wait a few minutes, or download the
  AppImage yourself and run the installer with `--appimage <file>`.
- **Dictionary audio is silent**: Kimochi plays audio through GStreamer and needs its base, good and
  bad plugins (the .deb installs them; with the AppImage, install them from your distribution).

## Steam Deck

- **Add to Steam fails with "Steam is not running"**: open Steam from the desktop, then try again, or
  add Kimochi yourself as a non-Steam game.
- **Kimochi's artwork is missing in Gaming Mode**: it appears once Steam restarts, as it does when you
  switch to Gaming Mode.

## Signing in

- **The code expired**: codes work for 10 minutes, once. Choose **Sign in** again in
  Settings → Account for a new one.
- **"Sign in to … again"**: this computer's sign-in was revoked or expired. Your data is still here;
  sign in again and Sync resumes.

## Still stuck?

Ask in [Kimochi's Discord](https://discord.gg/vdMge6TBZQ), or open an issue on
[GitHub](https://github.com/hamstu/kimochi/issues). Either way, say what you did and what you
expected to happen, and include Kimochi's debug info:

1. Open **Settings → About → Debug info**.
2. **Copy debug info** puts your Kimochi version, system and displays, OCR engine, dictionary,
   Kimochi's windows and recent errors on your clipboard, as text to paste.
3. For a GitHub issue, **Save debug bundle** saves the same with Kimochi's recent logs as a zip to
   attach. To catch more, turn on **Verbose logging** first, make the problem happen, then save the
   bundle. Verbose logging stays on until Kimochi quits.

Tokens, keys, e-mail addresses and your user name are left out of both. Nothing is sent anywhere
unless you send it.
