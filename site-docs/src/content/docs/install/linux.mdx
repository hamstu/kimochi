Kimochi has Linux builds for **x64** and **ARM64**, as an **AppImage** (any distribution) and a
**.deb** (Ubuntu, Debian, Mint, Pop!_OS).

<Tabs syncKey="linux">
  <TabItem label="One-line installer (recommended)">
    Open a terminal, paste this line and press <kbd>Enter</kbd>:

    ```sh
    curl -fsSL https://kimochiapp.com/install.sh | sh
    ```

    It installs the newest Kimochi AppImage for your CPU in your home folder, adds Kimochi to your
    app menu (under Education) and opens it. No administrator password is needed. Run it again to update in place; your settings,
    dictionaries and history are kept.

    Options, after `sh -s --`:

    | Option | What it does |
    | --- | --- |
    | `--no-launch` | Install or update without opening Kimochi afterwards. |
    | `--appimage <file>` | Install an AppImage you already downloaded. |
    | `--uninstall` | Remove Kimochi and its menu entries (your data is kept). |
    | `--help` | List the options. |

    For example: `curl -fsSL https://kimochiapp.com/install.sh | sh -s -- --no-launch`.
  </TabItem>
  <TabItem label=".deb (Ubuntu, Debian)">
    Download the `.deb` for your computer from [kimochiapp.com](https://kimochiapp.com/download/linux#debian),
    then install it from the folder you saved it to:

    ```sh
    cd ~/Downloads && sudo apt install ./kimochi_*.deb
    ```

    The .deb gets updates inside Kimochi too; each one asks for your password before it installs.
  </TabItem>
  <TabItem label="AppImage by hand">
    Download the `.AppImage` for your computer, make it executable and run it:

    ```sh
    cd ~/Downloads && chmod +x ./kimochi_*.AppImage && ./kimochi_*.AppImage
    ```

    Nothing happens? See [If Kimochi won't start](#if-kimochi-wont-start).
  </TabItem>
</Tabs>

## Choosing what to read

How Kimochi sees your screen depends on your desktop.

- **Wayland on GNOME, KDE Plasma 6, Hyprland, Sway 1.12+ and COSMIC**: Kimochi lists your screens and
  windows itself, with live previews, as on macOS and Windows: **Change source → Window or screen**.
  No desktop dialog, and nothing to link afterwards: Kimochi knows which window you chose, so the
  overlay follows it when you move, resize or full-screen it, hides while it's minimised or on another
  workspace, and **Bring to front** brings it back. On GNOME this needs the GNOME overlay extension
  (below); on Plasma 6.7 and older, the .deb (or Kimochi itself, when run as an AppImage) tells
  Plasma it may capture windows.
- **Other Wayland desktops**: your desktop shows its own dialog to choose the screen or window
  Kimochi may capture. **Change source → Choose New Source…** in the sidebar opens it. **Use Current
  Source** keeps the one you picked; Kimochi remembers it across restarts.
- **X11**: Kimochi lists your windows itself, as on macOS and Windows. Minimised windows and windows
  on other workspaces aren't listed.

### The overlay on Wayland

Drawing over other apps on Wayland needs the desktop's layer-shell support. On desktops without it,
**Show overlay** reads **Overlay unavailable**. On GNOME 46 to 51,
the [welcome guide](/welcome-guide/) sets up a small GNOME extension in its place that enables
screen annotations, dictionary pop-ups and desktop region selection (one monitor); the first time,
log out and back in once afterwards. If you skipped that step, **Set up** next to **Overlay unavailable**
in the sidebar does the same. Without either, **Crop area → Set OCR crop area…** (or **Set Anki crop area…**) opens a crop editor inside
Kimochi's window.

The overlay is tested on **KDE Plasma 6**, on **Hyprland** (on Omarchy), on **Sway** and on
**GNOME 46 to 51** with the GNOME overlay extension. On other desktops with layer-shell support, where
windows are chosen in the desktop's dialog, Kimochi can't tell where a shared *window* is, so the
overlay can't draw over it and the source card can't bring it to the front: share your whole screen
instead. You can still look up words in the Log.

### KDE Plasma

On Plasma, choose the game's **window** in Kimochi's list (or a whole screen). The overlay sits on
the game, follows it when you move it or send it to another monitor, and hides while the game is
minimised or on another desktop. **Bring to front** brings the game back.

Any screen works as a source, not only the one Kimochi opens on: in Plasma's screen-share dialog,
each screen, **Share full Workspace** (every monitor at once) and **Share virtual screen**. **Crop
area** opens on the monitor under your pointer, and the overlay's text follows the crop to its
monitor.

Hold <kbd>Shift</kbd> over the overlay's text to look words up and to click it, as on Windows and
macOS; without Shift, your clicks go through to the game. Kimochi sees Shift through Plasma's
**Legacy X11 App Support** setting (in System Settings), which by default lets apps see the modifier
keys whichever window is in front; the game still gets every key. If you set it to **Never**,
Kimochi can't see Shift, and you look a word up by **hovering** it instead. The first time Kimochi starts, Plasma
asks to confirm its global shortcuts (**Scan** and the **Controller menu**); change them any time in
**System Settings → Keyboard → Shortcuts**.

### Global shortcuts on Hyprland

Hyprland lists Kimochi's shortcuts but doesn't give them keys itself, so while Kimochi runs it
binds them for you: **Scan** and the **Controller menu** on the keys set in **Settings → Shortcuts &
Controls**, and <kbd>Shift</kbd> for the dictionary, without taking it from the game. These binds
last only while Kimochi runs and never touch your config; Kimochi adds them again when Hyprland
reloads. Once Kimochi has seen Shift through them, the overlay's text lets your clicks through to the
game until you hold Shift, as on Windows and macOS. Until then, hovering a word on the overlay looks
it up.

If your config already uses one of those keys for something else, Kimochi leaves it alone and
Settings says which. Choose another key there, or bind Kimochi's shortcut yourself. With Hyprland
0.56's Lua config (`~/.config/hypr/bindings.lua`, as on Omarchy):

```lua
hl.bind("CTRL + SHIFT + 8", hl.dsp.global("Kimochi:dev.kimochi.app.triggerScan"), { description = "Kimochi scan" })
hl.bind("CTRL + SHIFT + SPACE", hl.dsp.global("Kimochi:dev.kimochi.app.openControllerMenu"), { description = "Kimochi controls" })
hl.bind("Shift_L", hl.dsp.global("Kimochi:dev.kimochi.app.dictionaryShiftLeft"), { non_consuming = true, transparent = true, ignore_mods = true })
hl.bind("Shift_R", hl.dsp.global("Kimochi:dev.kimochi.app.dictionaryShiftRight"), { non_consuming = true, transparent = true, ignore_mods = true })
```

With the classic `hyprland.conf`:

```ini
bind = CTRL SHIFT, 8, global, Kimochi:dev.kimochi.app.triggerScan
bind = CTRL SHIFT, SPACE, global, Kimochi:dev.kimochi.app.openControllerMenu
bindnti = , Shift_L, global, Kimochi:dev.kimochi.app.dictionaryShiftLeft
bindnti = , Shift_R, global, Kimochi:dev.kimochi.app.dictionaryShiftRight
```

Reload Hyprland (or log out and back in) after editing.

## Updating

Kimochi updates itself when a new version comes out.

## Uninstalling

- **One-line installer** (including on a Steam Deck):

  ```sh
  curl -fsSL https://kimochiapp.com/install.sh | sh -s -- --uninstall
  ```

  Your settings and dictionaries are kept. To delete them too:

  ```sh
  rm -rf ~/.local/share/dev.kimochi.app ~/.config/dev.kimochi.app ~/.cache/dev.kimochi.app
  ```

- **.deb**: `sudo apt remove kimochi`

## If Kimochi won't start

The AppImage needs **FUSE 3**, which desktop installs usually come with (the Steam Deck does). The
one-line installer checks for it and, if it's missing, sets Kimochi up to run without it; it
starts a little slower. If you downloaded the AppImage yourself and it doesn't open, install FUSE 3
and try again:

| Distribution | Command |
| --- | --- |
| Ubuntu, Debian, Mint | `sudo apt install fuse3` |
| Fedora | `sudo dnf install fuse3` |
| Arch | `sudo pacman -S fuse3` |
| openSUSE | `sudo zypper install fuse3` |

More in [Troubleshooting](/help/troubleshooting/#linux).
